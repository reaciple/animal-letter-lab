# v1.5.1 추가 안내 · 2026-11-13

**1.4나 1.5를 먼저 적용할 필요 없습니다. 이번 v1.5.1 한 번만 적용하세요.** 기존 v1.4 캐릭터 변경·선택 확인·글씨 보존·도감 묶기와 v1.5 GPT 이야기 기능을 모두 포함합니다. 아래 순서대로 Worker와 GitHub 화면을 함께 교체합니다.

## 이야기 길이 설정
게임 → 부모님 → GPT 이야기와 질문 → 이야기 길이 → ‘짧게 · 1~2분’, ‘보통 · 3~4분’, ‘길게 · 5~6분’ 선택 → 이야기 설정 저장.
기본은 보통(3~4분)입니다. 설정 저장 후 새로 생성하는 이야기부터 적용됩니다. 두 아이가 공유하는 이 기기의 설정이며, 질문은 모든 길이에 4개입니다. 이미 저장된 이야기와 진행 중 요청은 설정 변경만으로 다시 생성되거나 과금되지 않습니다. 읽는 시간은 추정치이며 읽는 속도와 대화에 따라 달라집니다. 길수록 텍스트 비용이 늘 수 있습니다.

## 도감은 어디에 저장되나요?
| 내용 | 저장 장소 |
| --- | --- |
| 등록한 카드 사진, 생성한 합체·식사 그림, 친구 이름과 손글씨, 이야기 본문·질문, 설정 | 게임을 사용하는 기기·브라우저의 IndexedDB 저장 공간 |
| 게임 화면과 실행 코드, 기본 제공 이미지 | GitHub Pages |
| OpenAI API 키와 가족 연결 코드 | Cloudflare Worker의 비밀 설정 |
| 요청 횟수·처리 상태, GPT 이야기 결과의 복구용 사본 | 사용자 Cloudflare 계정의 D1 데이터베이스 |

Cloudflare D1에는 도감 그림을 저장하지 않습니다. 그림은 Worker를 거쳐 OpenAI에 전달되어 생성되지만, 게임의 장기 사진 보관 장소는 기기 브라우저입니다. 이야기의 D1 사본은 응답 유실·중복 호출 방지용으로, 전체 도감 백업이나 기기 간 자동 동기화가 아닙니다. 게임에서 사진을 삭제해도 요청 장부와 서버의 이야기 사본을 삭제하는 기능은 현재 없습니다.

같은 Galaxy Tab S7이라도 Chrome과 삼성 인터넷은 저장 공간이 다릅니다. PC·휴대폰에서도 자동으로 같은 도감이 나오지 않습니다. 브라우저 사이트 데이터 삭제·기기 초기화 시 도감이 사라질 수 있으니 ‘도감 전체 백업’으로 파일을 받아 보관하세요. 같은 주소와 같은 브라우저에서 코드만 업데이트하면 기존 자료는 유지됩니다.

백업 파일에는 등록 사진·그림·이름·이야기·질문·설정이 포함됩니다. 이 파일을 Google Drive 등에 보관하거나 다른 기기에서 복원할 수 있습니다. 진행 중 연습 획과 API 연결 코드는 백업 대상이 아닙니다. 다른 기기에서 새 생성을 하려면 연결도 별도로 설정해야 합니다.

## 적용 후 간단 확인
1. 하단 v1.5.1 및 부모님 화면의 서버 버전을 확인합니다.
2. 이야기 길이를 짧게로 저장하고 설정 화면을 다시 열어 유지되는지 확인합니다.
3. 기존 먹이주기 후 그림에서 GPT 이야기 만들기를 누르면 이미지 추가 생성 없이 이야기만 시험할 수 있습니다(텍스트 비용 발생).
4. 도감에서 다시 열었을 때 본문·질문이 그대로 나타나는지 확인하고 전체 백업을 받습니다.

# 꼬물꼬물 동물연구소 v1.5.1 업데이트

이번 파일을 적용하면 GPT가 매번 새로운 이야기와 질문을 만듭니다. 파일 제공만으로 운영 사이트가 변경되지는 않습니다.

## 업데이트 방법
1. 아이들이 쓰는 기존 게임의 부모님 화면에서 전체 백업을 받습니다. 같은 주소와 브라우저를 사용하고 사이트 데이터를 지우지 마세요.
2. animal-letter-lab-update-v1.5.1.zip을 풀어 주세요.
3. Cloudflare 대시보드 → 현재 게임 Worker → Edit code에서 worker/cloudflare-worker.js 전체 내용으로 기존 코드를 교체하고 Deploy합니다.
4. 기존 OPENAI_API_KEY, FAMILY_TOKEN, ALLOWED_ORIGIN, DB 바인딩을 유지하세요. 새 키나 DB는 필요 없습니다. 이야기용 테이블은 첫 요청 때 자동 생성되므로 SQL을 별도로 실행할 필요 없습니다. 기존 API 키를 제한 권한으로 만들었다면 Responses API 요청 권한도 있어야 합니다.
5. GitHub에서 현재 두 번째 게임 저장소 → Add file → Upload files를 엽니다. github-pages 폴더 **안의** index.html, assets 폴더와 안내 파일들을 기존 index.html과 같은 위치에 업로드하고 Commit changes합니다. github-pages 폴더 자체나 source, worker를 올리지 마세요. 기존 이미지 폴더는 삭제하지 마세요.
6. GitHub 배포 완료 후 기존 게임 주소를 새로고침합니다. 하단 v1.5.1을 확인하고 부모님 → 저장하고 연결 확인에서 서버도 최신인지 확인합니다. 화면이 오래된 상태라면 탭을 닫았다 다시 열어 주세요. 사이트 데이터 삭제는 하지 마세요.
7. 기존 먹이주기 후 사진을 도감에서 열고 ‘GPT 이야기 만들기’를 눌러 시험할 수 있습니다. 이 경우 그림을 새로 만들지 않고 텍스트 요청만 발생합니다. 새 먹이주기는 식사 그림 저장 후 이야기를 자동 생성합니다.
8. 이야기와 질문 4개가 보이는지 확인한 뒤 전체 백업을 다시 받으세요.

## 이야기 방식
- 모델: gpt-6-luna / Responses API. 미리 준비한 이야기를 섞는 방식은 제거했습니다.
- 선택한 두 동물·캐릭터, 소품, 색, 집, 먹이를 바탕으로 유쾌한 오해, 엉뚱한 시도, 반전과 웃음이 있는 새 이야기를 요청합니다.
- 부모가 부모님 설정에서 선택한 약 1~2분 / 3~4분 / 5~6분 분량을 목표로 합니다. 실제 시간은 읽는 속도와 대화에 따라 달라집니다.
- 질문은 기억·마음·상상·놀이 4개이며 부모용 대화 힌트도 제공합니다.
- 이 기기의 최근 이야기 6개의 제목과 줄거리를 참고해 비슷한 전개를 피하도록 지시합니다. 모든 이야기의 완전한 비중복을 보장하는 방식은 아닙니다.
- 이야기 API에는 선택 정보와 최근 줄거리만 전송합니다. 사진을 직접 분석하는 방식이 아니며 아이 이름·손글씨는 보내지 않습니다. 이미지 생성에는 기존과 같이 참조 사진을 사용합니다.
- 새 먹이주기 결과마다 새 이야기를 만듭니다. 저장된 이야기를 다시 읽거나 인쇄할 때는 API를 호출하지 않습니다.
- 이전 짧은 이야기는 유지되며 해당 사진에서 GPT 이야기 만들기를 선택하면 새 이야기로 교체할 수 있습니다.

## 비용과 실패 처리
텍스트 생성은 이미지 비용과 별도입니다. 기본 이야기 한도는 가족 전체 하루10회·월120회이며 이미지 한도와 독립적입니다. 필요하면 Cloudflare Worker의 Variables에 MAX_DAILY_STORIES, MAX_MONTHLY_STORIES를 설정할 수 있습니다(최대30/500). 날짜는 한국시간 기준입니다. 게임의 이미지 요청 횟수 초기화로 이야기 횟수까지 초기화되지는 않습니다.

그림을 먼저 저장하므로 이야기 실패로 그림이 사라지지 않습니다. 응답이 끊기면 ‘이전 이야기 요청 결과 확인’을 먼저 누르세요. 서버에 완료된 결과가 있으면 새 GPT 호출 없이 가져옵니다. 완료된 결과가 없고 다시 만들기를 선택하면 추가 비용이 생길 수 있습니다. 실패·시간초과 요청도 한도에 포함하며 자동으로 유료 재시도하지 않습니다.

이야기는 기기 도감과 백업에 저장되며, 중복 호출 방지와 응답 복구를 위해 Cloudflare D1에도 요청ID와 결과를 저장합니다. 사진과 API 키는 D1에 저장하지 않습니다. 백업 v5는 전체 이야기와 질문을 포함하며 이전 v1~v4도 복원합니다.

## 이번 업데이트에 필요한 파일
사진을 새로 만들 필요는 없습니다. v1.4.0 캐릭터·쓰기 보존·도감 묶기 기능도 포함합니다. 아직 캐릭터 사진을 준비하지 않았다면 동봉된 CHARACTER-PROMPTS-v1.4.0.txt를 사용하세요.
전체 ZIP은 최신 원본 보관용, 작은 업데이트 ZIP은 이번 배포용입니다. 다음 수정이나 새 채팅에서는 전체 ZIP과 PROJECT-HANDOFF.md를 전달해 주세요.

타입 검사, 프로덕션 빌드, 자동 테스트 32개 및 브라우저 모의 응답 검증을 수행했습니다. 실제 유료 API 호출, 사용자 GitHub/Cloudflare 배포, 실물 프린터 확인은 수행하지 않았습니다. STORY-EXAMPLE-v1.5.1.md는 설명용 창작 예시이며 실제 사용자 API 호출 결과가 아닙니다.
