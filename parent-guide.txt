# 캐릭터연구소 v1.6.0 · 우리 친구 그림책

## 이번 업데이트
짧게 4장, 보통 6장, 길게 8장. 각 장은 짧은 2~4문장과 해당 장면의 삽화 한 장입니다. 처음 사용하는 기기의 기본값은 짧게이며 기존 사용자의 길이 설정은 유지됩니다. 부모님 설정에서 짧게를 선택하고 저장하면 다음 새 이야기부터 적용됩니다.
주인공 이름만 이야기의 필수 소재로 사용합니다. 캐릭터 합체 재료, 생김새, 소품, 집, 먹이를 모두 설명할 필요가 없고 교훈이나 반전을 강요하지 않습니다. 익숙한 행동, 한 장소, 작은 사건 하나로 쉽고 즐겁게 씁니다.
합체캐릭터의 원본 사진(남아 있다면 먹이주기 전 그림)을 모든 삽화에 참고합니다. 2장부터는 첫 장 그림도 함께 보내 그림체를 맞춥니다. 그림은 부드러운 동화풍이며 한글은 게임이 그림 위에 표시하므로 생성 모델의 한글 철자 오류를 피합니다. 생성 모델의 특성상 장마다 외형이나 세부 배경이 조금 달라질 수 있습니다.
원고와 삽화를 한 도감 작품 안에 저장합니다. 한 장씩 넘겨 읽기, 크게 읽기, 질문 접어 두기, 기존 인쇄에서 그림책 장별 인쇄를 지원합니다. 기존에 완성한 텍스트 이야기는 그대로 남고 자동으로 다시 생성되거나 비용이 발생하지 않습니다. 이번 버전은 새로 생성하는 이야기부터 그림책입니다.

## 설치 순서: Cloudflare와 GitHub 둘 다 업데이트
1. 현재 게임 → 부모님 → 도감 전체 백업을 내려받아 보관합니다.
2. Cloudflare → 기존 Worker → Edit code에서 worker/cloudflare-worker.js 내용을 전체 교체하고 Deploy 합니다. 기존 API 키, FAMILY_TOKEN, ALLOWED_ORIGIN, DB 바인딩은 그대로 사용합니다. DB를 삭제하거나 새로 만들지 마세요. 새 삽화 테이블은 첫 사용 때 자동으로 생성되며 별도 SQL 실행은 필요 없습니다.
3. GitHub animal-letter-lab 저장소 → Add file → Upload files에서 github-pages 폴더 **안의 파일과 폴더 전부**를 기존 배포 위치에 올리고 Commit changes 합니다. index.html만 교체하면 안 됩니다. assets 폴더도 반드시 함께 올립니다. github-pages라는 폴더를 한 겹 추가하지 마세요.
4. GitHub Actions 배포 완료 후 게임을 새로고침합니다. 하단 v1.6.0과 부모님 → 저장하고 연결 확인의 서버 v1.6.0을 확인합니다. 이전 화면이면 탭을 닫고 다시 열거나 캐시를 무시한 새로고침을 합니다. 도감이 있으므로 사이트 저장소/데이터를 지우지 마세요.
5. 부모님 → 그림책과 질문 → 그림책 길이에서 ‘짧게 · 그림책 4장’을 선택하고 이야기 설정 저장을 누릅니다. 캐릭터 사진 재등록은 필요 없습니다.
6. 평소처럼 합체 → 먹이주기 → 이름 쓰기/텍스트 이름 입력 → ‘그림책 생성하기’를 누릅니다. 원고가 먼저 저장되고 그림을 차례로 만듭니다. 완성되면 ‘그림책 크게 읽기’를 누르고 아이와 한 장씩 넘깁니다.
source 폴더는 개발 원본이므로 배포할 필요는 없지만 다음 업데이트를 위해 ZIP과 함께 보관하세요. 이전 업데이트를 차례로 설치하지 않아도 이 누적본을 바로 적용할 수 있습니다.

## 요청 수와 비용
한 권당 이야기 텍스트 요청 1회 + 삽화 4/6/8회입니다. 예를 들어 짧게로 처음부터 합체·먹이주기·그림책까지 만들면 합체 1장 + 먹이 1장 + 삽화 4장 = 이미지 총 6회, 텍스트 1회입니다. 그림책 삽화도 OpenAI API 별도 비용이 발생합니다. 참조 이미지 입력 비용도 포함될 수 있습니다. 모든 삽화는 기존에 사용 중인 gpt-image-2.5-flare, low, 1024×1024, JPG로 요청합니다. 기존 이야기 모델 선택은 유지합니다.
삽화를 기존 하루 합체 한도 4회에 포함하면 한 권을 끝내기 전에 막힐 수 있어 한도를 분리했습니다. 다음 변수는 등록하지 않으면 기본값을 사용합니다.

| 대상 | Cloudflare 변수 | 기본값 |
|---|---|---:|
| 그림책 삽화 하루 | MAX_DAILY_BOOK_IMAGES | 16장 |
| 그림책 삽화 월 | MAX_MONTHLY_BOOK_IMAGES | 240장 |

합체·먹이주기의 MAX_DAILY_REQUESTS/MAX_MONTHLY_REQUESTS, 이야기의 MAX_DAILY_STORIES/MAX_MONTHLY_STORIES는 기존 설정 그대로입니다. 하루/월은 한국 시간 기준입니다. 실패/결과 불명 요청도 횟수에 포함합니다. ‘오늘 요청 횟수 초기화’와 ‘오늘 이야기 요청 횟수 초기화’는 삽화 횟수를 초기화하지 않습니다. 삽화 한도는 부모님 화면에서 확인할 수 있습니다. 필요하면 위 두 변수를 Cloudflare 설정에 Number가 아닌 일반 Variable 문자열 값(예: 16, 240)으로 추가하고 저장·배포하세요. 새 변수 추가는 필수가 아닙니다.

## 중단과 복구
- 각 장을 완성하는 즉시 도감에 저장합니다. ‘이번 장까지 만들고 쉬기’는 현재 요청을 끝낸 후 다음 장 요청을 멈춥니다. 이미 시작한 유료 요청은 취소되지 않습니다.
- 도감 → 해당 먹이주기 작품 → ‘남은 그림 이어 만들기 · 먼저 결과 확인’으로 돌아옵니다. 완성한 장과 원고를 다시 생성하지 않습니다.
- 결과가 불확실하면 같은 요청을 조회합니다. 자동으로 유료 재시도하지 않습니다. 실패한 요청을 다시 만들 때만 추가 비용 안내 후 새 요청을 보냅니다.
- 기다리는 중 탭을 닫아도 서버에 완료된 삽화가 저장됐다면 7일 내 같은 요청으로 복구할 수 있습니다. 요청 자체가 중단되었거나 서버에도 저장되지 않았다면 복구를 보장하지 못합니다.

## 어디에 저장되나요?
완성된 그림책 원고·질문·삽화는 현재 기기/브라우저의 IndexedDB 도감에 저장됩니다. 새 전체 백업 v6에도 삽화가 포함됩니다. 다른 기기로 옮기려면 전체 백업/복원을 사용합니다. v6 백업은 예전 버전 게임에서 복원할 수 없습니다. 기존 v1~v5 백업은 새 버전에서 복원 가능합니다.
Cloudflare D1에는 기존처럼 이야기 원고와 요청 기록이 저장되며, 이번 버전부터는 연결 복구용 삽화 사본도 조각으로 나누어 저장합니다. 서버 삽화 사본은 생성 후 7일이 지나면 다음 삽화 관련 접속 때 정리합니다. 브라우저에 저장한 삽화는 이 기간과 관계없이 유지됩니다. 참조 원본 사진과 API 키를 D1에 저장하지 않습니다. 별도의 R2 가입이나 설정은 추가하지 않았습니다. 그림책이 쌓이면 기기 저장량과 백업 파일 크기가 늘어납니다.

## 검증 범위
48개 자동 테스트, TypeScript 검사, 배포용 빌드 완료. 4/6/8장과 2~4문장 검사, 원본/스타일 참조, 중복 요청, 한도, 일부 실패, 연결 복구, 서버 사본 만료, 도감 저장/이름 수정/백업 복원을 검증했습니다. 브라우저에서 장 넘김·긴 문단 배치·부모님 장수 설정을 확인했습니다. 사용자 Cloudflare/GitHub에 직접 배포하거나 실제 유료 API를 호출하지 않았습니다. 실제 이야기 재미와 장별 캐릭터 일관성은 배포 후 첫 그림책에서 확인해 주세요.
